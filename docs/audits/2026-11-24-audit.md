# Audit: topic-tree-generator v2 (`feature/topic-tree-v2`)

Date: 2026-11-24 · Depth: **Deep** (all 12 dimensions + line-by-line review of every high-risk module) · Baseline: `c5b14a6` (`feature/topic-tree-v2` vs `main`).

## 1. Executive Summary

The `topic-tree` v2 service is well-structured, modular, and closely aligned with the v2 Use-Case Specification, the "Themenbäume" design guidelines, and the Team 6 service guide (Leitfaden). The core architecture cleanly separates HTTP, pipeline orchestration, pure domain logic, and LLM transport, with zero circular dependencies and every new module under 180 lines. Before handing off to Team 6, **4 major correctness/resilience defects** (duplicate keys in `merge`, `refs.py` header/size/concurrency crashes, empty `fulltext.text`/`shaping` edge cases, and locked-node/content-duplication bugs in `refine`) and **1 test-isolation defect** (4 tests failing when host env has `OPENAI_API_KEY` or on Windows) should be fixed — all are localized and fixable in under a day.

## 2. Overview

- **Stack**: Python 3.13, FastAPI, Pydantic v2, pydantic-settings, OpenAI async SDK (1.99.9), httpx, loguru, gunicorn + uvicorn-worker, prometheus-client, uv, Helm v2 chart, GitLab CI + GitHub Actions.
- **Purpose**: Generates and refines edu-sharing collection trees ("Themenbäume") across four use cases (`topic`, `document`, `folders`, `contents`) while preserving v1 endpoints (`/generate-topic-tree`, `/generate-collection-description`) unchanged.
- **Coverage**: Read 100% of `app/` (excluding frozen `app/legacy/dtos/` and `app/legacy/prompts.py`), 100% of `deploy/helm/topic-tree/`, `Dockerfile`, `compose.yml`, `.gitlab-ci.yml`, `.github/workflows/ci.yml`, `scripts/`, `docs/`, and targeted test suites.
- **Automated scanners run**: `uv run pytest -q`, `uv run ruff check`, `uv run ruff format --check`, `uv run ruff check --select S,B,C90,BLE,TRY app`, `helm lint --strict deploy/helm/topic-tree`, and strict JSON Schema validation across all 9 LLM output models. Docker daemon was not running locally (static Dockerfile/Compose check only).

## 5. Top Issues

1. **[High] Logic — Duplicate keys in `merge` silently delete the node**
   - File: `app/domain/ops.py` · Lines: `114–127` (`_Applier.merge`)
   - Problem: `change.keys = ["k-optik", "k-optik"]` passes schema validation (`len >= 2`), duplicates children, and calls `_detach(self.roots, other.key)` on `first`, deleting the node. Merging two distinct nodes with shared content IDs also creates duplicate `ContentRef` entries.
   - Impact: Data loss in `refine` when an LLM or caller emits duplicate keys in `merge`.
   - Fix: Deduplicate `change.keys` preserving order; reject if `< 2` unique keys; deduplicate `contents` by `id` (keeping max confidence).

2. **[High] Security / Resilience — Unhandled exceptions and unbounded concurrency in `refs.py`**
   - File: `app/pipeline/inputs/refs.py` · Lines: `52, 80–97` (`fetch_text`, `_with_fulltext`, `resolve_refs`)
   - Problem: Malformed `Content-Length` raises unhandled `ValueError` (500); fetched text between 2 MB and 10 MB crashes `Fulltext(text=...)` (`max_length=2_000_000`) with unhandled `ValidationError` (500); `asyncio.gather` spawns up to 5,000 concurrent `httpx.AsyncClient` connections without a semaphore.
   - Impact: DoS / socket exhaustion or 500 crashes when fetching `items_ref` / `fulltext.ref`.
   - Fix: Parse `content-length` safely; enforce `Fulltext` character limit as 422 `REF_TOO_LARGE`; bound ref fetches with a semaphore and reuse a single client per `resolve_refs`.

3. **[High] Logic — Unhandled `IndexError` (500) on empty `fulltext.text` in `document`, empty `shaping` in `contents`**
   - File: `app/pipeline/input_checks.py` (`43–50`) & `app/pipeline/strategies/document.py` (`32, 97–101`)
   - Problem: `Fulltext.text = ""` passes `item.fulltext` truthiness check in `input_checks`, then gets filtered out in `document.py`, causing `docs[0]` `IndexError`. `contents` with all `use: ["content"]` items sends an empty prompt.
   - Impact: 500 error on valid-looking JSON requests; wasted LLM calls on invalid `contents` requests.
   - Fix: Validate non-empty text/ref for `document` structure docs (both pre- and post-`resolve_refs`) and require ≥ 1 `structure` item for `contents`.

4. **[High] Logic — `refine` mutates locked nodes without descriptions and duplicates removed contents**
   - File: `app/pipeline/strategies/refine.py` (`48–51, 96`) & `app/pipeline/orchestrator.py` (`55–63`)
   - Problem: `refine.py:96` sends any node with empty `description` to `describe_nodes` even if it is locked or under a locked ancestor. Removing a node puts its contents in `result.unassigned`, after which `_assign` re-processes those same IDs if present in `req.items`.
   - Impact: Violates `locked` contract and produces duplicate/contradictory content assignments.
   - Fix: Exclude `protected_keys` from `describe_nodes` targets; exclude already-`unassigned` IDs in `_assign`.

5. **[High] Testing — Host environment leaks into tests & Windows gunicorn smoke failure**
   - File: `tests/llm/test_backend.py`, `tests/observability/test_internal_server.py`, `tests/test_gunicorn_smoke.py`
   - Problem: `Settings(_env_file=None)` still reads `os.environ`, causing 3 test failures whenever `OPENAI_API_KEY` is set in the shell. `test_gunicorn_smoke.py` invokes POSIX-only `gunicorn` unconditionally on Windows.
   - Impact: Non-deterministic test suite on developer machines.
   - Fix: Add `tests/conftest.py` autouse fixture clearing service env vars; skip POSIX-only gunicorn test on `win32` and add a cross-platform dual-port + HTTP stub E2E test.

6. **[Medium] API / Leitfaden — Upstream b-api 401/403 errors mapped to 502**
   - File: `app/pipeline/orchestrator.py` · Lines: `44–52` (`_llm_unavailable`)
   - Problem: In b-api mode, an upstream 401 (expired/out-of-scope delegation token) or 403 (missing LLM permission) is returned as 502 `LLM_UNAVAILABLE` instead of 401/403 (Leitfaden Kap. 1 & 2.2: 4xx for caller errors, 5xx only for service errors).
   - Fix: When running in `bapi` mode, map upstream 401 → 401 `UNAUTHORIZED` and 403 → 403 `FORBIDDEN`.

## 6. All Findings (Additional Medium / Low)

- **[Medium] Logic** `app/domain/tree.py:90` (`from_tree_in`): `c.confidence or 1.0` coerces `0.0` to `1.0`. Use `1.0 if c.confidence is None else c.confidence`.
- **[Medium] Performance** `app/pipeline/input_checks.py:28` (`_check_items`): `ids.count(i)` in comprehension is `O(n²)` on up to 5,000 items. Use `collections.Counter`.
- **[Medium] Spec/Plan** `app/pipeline/steps/describe_nodes.py:45–51` (`_describe_batch`): Plan T3.5 specifies warning when LLM returns unknown keys; currently dropped silently.
- **[Medium] Spec** `app/pipeline/strategies/folders.py:49–52` + `app/pipeline/steps/improve_folders.py:50`: Supplementary `structure` items are not passed to `improve_folders` (unlike `topic`).
- **[Medium] API** `app/pipeline/finalize.py:105–107` (`_audience`): Hardcodes only `teacher`/`learner`; should fall back to `app.vocab.labels.label(r)` for all OEH roles before falling back to URI slug.
- **[Medium] Deployment** `.gitlab-ci.yml:12,83–90` & `deploy/helm/topic-tree/values.yaml:6`: Image name differs (`topic-tree-generator` vs `topic-tree`); `.gitlab-ci.yml` lacks a release job to package/push the Helm chart on tags `vX.Y.Z` (Leitfaden Kap. 4).
- **[Low] Testing** Plan T6.3 calls for `tests/stub_openai.py` + live E2E server test; not yet present.
- **[Low] Pre-existing (out of scope)** `app/legacy/router.py` (396 lines, cyclomatic complexity 26, logs full request body): intentionally frozen per E7 for backward compatibility.
